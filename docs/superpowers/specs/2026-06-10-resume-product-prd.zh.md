## 1. 摘要

### 一句话定位

**Resume Studio 是一款本地优先（local-first）的桌面级简历编辑器**：用户在不上传任何个人数据到第三方服务器的前提下，完成「写 → 改 → 调 → 导出」的全流程，并通过可选的 AI / ATS 工具提升求职竞争力。

### 关键差异点（与 FlowCV / Resume.io 等 SaaS 对比）

1. **数据自主**：简历 JSON 保存在用户本地 `appData` 目录，可随时备份、迁移、版本控制。
2. **多语言原生**：内置 zh-CN / en-US 双词典，UI 与简历内容均可独立切换语言；数据模型不绑定任何单一语言。
3. **可扩展架构**：Rust workspace 内核 + Tauri + React 外壳；新增 section 类型、新增渲染器、新增导出格式都是「加文件」而不是「改框架」。
4. **AI 可插可拔**：AI 改写、ATS 评分均为可选模块；用户填入自己的 API Key 才启用，无强绑定。
5. **视觉一致**：白蓝调（`#0066FF`）设计语言贯穿编辑器、预览、导出三端，所见即所得。

## 2. 背景与机会

### 用户痛点

- **隐私顾虑**：主流 SaaS 简历工具要求上传所有个人信息到服务器，部分用户（尤其是有保密协议、转行期、海外身份）有强烈的本地化诉求。
- **多版本管理混乱**：求职者通常需要为不同岗位维护多份简历，Word / Google Docs 难以统一管理。
- **中英文混排痛点**：跨境求职用户在中英文版本切换时，需要同时维护两份不同的文件，数据无法同源。
- **ATS 黑盒**：投递后简历是否能被 ATS 解析、关键词是否命中，用户没有可量化反馈。
- **AI 助力但不替代**：用户希望 AI 帮助打磨措辞，而不是「一键生成全篇」失去个人特色。

### 竞品现状（速览）

| 产品              | 数据存放 | 多语言 | AI | ATS | 模板生态 | 桌面端 |
| ----------------- | -------- | ------ | -- | --- | -------- | ------ |
| FlowCV            | 云端     | 弱     | 有 | 弱  | 中       | 否     |
| Resume.io         | 云端     | 弱     | 有 | 有  | 强       | 否     |
| Reactive Resume   | 自托管   | 中     | 弱 | 无  | 中       | 否     |
| Canva Resume      | 云端     | 弱     | 弱 | 无  | 极强     | 否     |
| **Resume Studio** | **本地** | **强** | 可选 | **有** | 中→强  | **是** |

### 市场机会

- 远程办公 + 跨境求职常态化，多语言简历需求增长。
- 隐私意识提升，「数据不出本机」成为差异化卖点。
- LLM 普及让 AI 改写文案的成本接近零，门槛在工具集成。

## 3. 目标用户

### Persona A：应届毕业生「小林」

- 年龄 22，无社会经验。
- 痛点：不知道简历该写什么、模板太丑、不会改 Word。
- 期望：模板好看、有示例填空、有 AI 帮忙润色。
- 优先级权重：**易用性 > AI 助力 > 模板**。

### Persona B：中级软件工程师「Quan」

- 年龄 28，已工作 5 年，跳槽 2 次。
- 痛点：维护中英双语简历同步麻烦，每次投递要针对岗位调整关键词。
- 期望：一份数据生成两种语言；ATS 评分快速反馈；导出 PDF 像素级精准。
- 优先级权重：**多语言 > ATS > 数据可控**。

### Persona C：高级专业人士「李博士」

- 年龄 38，海外学者，求职目标多元（教职、企业研发、咨询）。
- 痛点：同一份履历要包装成三种不同侧重；项目/论文/奖项条目极多。
- 期望：完整 15 类 section 支持、可隐藏/重排 section、模板支持长简历分页。
- 优先级权重：**section 类型完整度 > 多版本管理 > 排版可控**。

### Persona D：设计敏感型用户「Aria」

- 年龄 30，产品/设计岗，对视觉有强主张。
- 痛点：大部分简历工具排版死板，模板不能微调。
- 期望：颜色 / 字体 / 间距 / 布局可精细控制；可上传照片；模板可换肤。
- 优先级权重：**Customize 颗粒度 > 模板美感 > 实时预览**。

## 4. 业务目标与成功指标

### 北极星指标

**完成首份简历导出的用户占比（D7 内）** ≥ 60%。

### 核心 KPI

| 维度       | 指标                                       | 目标（v1.0 GA 半年内） |
| ---------- | ------------------------------------------ | ---------------------- |
| 激活       | 新装用户 D1 创建/导入一份简历              | ≥ 80%                  |
| 留存       | D30 回访率                                 | ≥ 35%                  |
| 完成度     | 平均每份简历 section 数                    | ≥ 5                    |
| AI 使用率  | 启用 AI 工具的用户占比                     | ≥ 25%                  |
| 多语言渗透 | 同时维护两种语言版本的用户占比             | ≥ 15%                  |
| 导出成功率 | PDF 导出端到端成功率                       | ≥ 99%                  |

## 5. 产品范围

### In Scope（v1.0 完整产品）

- 本地简历 JSON 持久化、原子写入。
- Editor 三视图：Content（内容） / Customize（个性化） / AI Tools（AI 工具）。
- 15 类 section（Summary / Experience / Education / Skills / Projects / Languages / Certifications / Interests / Awards / Publications / References / Volunteering / Courses / CustomSection / Header）。
- Customize 14 个子面板（Document / Templates / Layout / FontSize / Spacing / Entries / Headings / Font / Colors / Header / Photo / Links / Footer / Sections）。
- 多模板系统（内置 4–8 套 + 用户自加载）。
- 实时预览（嵌入 HTML 渲染）。
- 导出 PDF / HTML / Markdown / DOCX / JSON。
- AI 工具：bullet 润色、summary 改写、Cover Letter 草稿。
- ATS 评分：输入 JD → 输出维度评分 + 改进建议。
- 多简历管理：列表、新建、复制、删除、导入（FlowCV / LinkedIn JSON）。
- Cover Letter 编辑器（共用 Personal 信息）。
- 双语切换（zh-CN / en-US；UI 与简历内容独立可切）。
- 照片上传与裁剪。
- 全局 Undo / Redo。

### Out of Scope（v1.0 不做）

- 云端账户与跨设备同步。
- 协作编辑、评论、分享链接。
- 浏览器版（仅桌面端 Tauri）。
- 模板市场的付费/交易系统。
- 简历投递追踪（CRM 风格）。
- 面试模拟、岗位推荐。
- 多 LLM 厂商（v1.0 仅集成 Anthropic Claude API）。
- 移动端原生 app。
- 简历 ↔ LinkedIn 双向自动同步（仅支持单向导入）。

## 6. 用户角色与权限

v1.0 为单机单用户产品，不存在多角色概念。**所有权限均为本地文件系统层面**：

- 简历文件读写：用户对自己 `appData` 目录的完整权限。
- AI Key：存放于系统 keyring（macOS Keychain / Windows Credential Manager / Linux libsecret），与简历 JSON 物理隔离。
- 照片文件：与简历 JSON 同目录的 `photos/` 子目录，引用以相对路径。

未来如开放云同步，将引入「账户」角色，但不在本 PRD 范围内。

## 7. 关键用户旅程

### Journey 1：首次使用 → 导出第一份简历

```
启动 App
  → Overview 页面：无简历，显示「新建」「导入」两个 CTA
  → 选「新建」→ 输入简历名 → 进入 Editor / Content
  → PersonalSection 已展开为编辑态，填写姓名 + 联系方式
  → 点击「+ 添加内容」→ 浮窗选「工作经历」→ 卡片创建并自动展开为编辑态
  → 填一条经历 → 保存 → 卡片回到 expanded
  → 重复添加 Education / Skills
  → 切到 Customize / Templates → 换模板 → 实时预览刷新
  → 点击 TopNav 的「下载」按钮 → 选 PDF → 系统保存对话框 → 完成
```

**成功标准**：D1 用户中 ≥ 80% 完成至少一次「新建 → 导出」闭环。

### Journey 2：维护中英双语版本

```
已有中文简历「Resume-中」
  → Overview 选中 → 「复制」→ 命名「Resume-EN」
  → 进入 Editor → TopNav 切换该简历的 locale 为 en-US
  → AI Tools → 选「翻译全文」（v1.1 能力，v1.0 手工逐条改）
  → 逐条改写后导出 PDF
  → 两份简历并存于 Overview，互不影响
```

**成功标准**：用户能在 ≤ 15 分钟内基于既有简历产出另一语言版本。

### Journey 3：针对岗位 ATS 优化

```
Editor / AI Tools → ATS 面板
  → 粘贴 JD 文本 → 点击「评分」
  → 输出总分 + 4 维度（关键词覆盖、长度、结构、格式合规）
  → 每个低分维度给出可点击的改进建议
  → 点击建议 → 跳转到对应 section 编辑态 → 修改 → 保存
  → 重新评分 → 分数提升
```

**成功标准**：用户三次以内迭代能将 ATS 分数提升 ≥ 15 分。

### Journey 4：AI 润色单条 bullet

```
Editor / Content → 展开 Experience → 编辑某条 bullet
  → bullet 输入框右侧出现「AI 润色」按钮
  → 点击 → 流式输出三个候选改写 → 选择 → 应用
  → Undo 可回退
```

**成功标准**：单次润色 P95 响应 ≤ 5 秒；用户接受率（不立即 Undo）≥ 50%。

## 8. 功能模块需求

### 8.1 简历管理（Overview）

**优先级**：P0

| ID    | 功能         | 描述                                                                 | 验收要点                                            |
| ----- | ------------ | -------------------------------------------------------------------- | --------------------------------------------------- |
| OV-01 | 简历列表     | 卡片网格展示所有本地简历，每卡片显示名称、缩略图、最近编辑时间       | 空状态显示「新建」「导入」两个引导按钮              |
| OV-02 | 新建简历     | 点击新建 → 命名 → 进入 Editor，新简历包含空白 PersonalInfo 与空 sections | 命名重复自动追加序号                                |
| OV-03 | 复制简历     | 任一卡片右上角菜单中「复制」→ 新简历命名为「原名 (副本)」               | 复制为深拷贝，互不影响                              |
| OV-04 | 删除简历     | 二次确认对话框；删除后文件物理移到回收站（不直接 unlink）             | 误删可从系统回收站恢复                              |
| OV-05 | 导入简历     | 支持 JSON Resume Schema、FlowCV JSON、LinkedIn 导出 PDF（OCR）       | 字段不匹配走 best-effort，未识别字段进入 CustomSection |
| OV-06 | 重命名简历   | 卡片右上角菜单中「重命名」→ 行内编辑                                  | 不允许空名                                          |
| OV-07 | 排序与筛选   | 默认按最近编辑时间倒序；支持按名称、按 locale 筛选                    | 选项持久化到 settings                               |

| Layout        | 单列 / 双列 / 上下分栏；侧栏宽度 slider；左右翻转                                              | P1     |
| Font Size     | 全局缩放（80% – 120%）；分别控制标题 / 正文 / 元信息                                          | P1     |
| Spacing       | 行距、段距、卡片间距、页边距 slider                                                            | P1     |
| Entries       | 条目内部对齐方式、日期对齐、项目符号样式                                                       | P1     |
| Headings      | 标题样式（大写 / 标题样式 / 强调）、下划线、颜色块                                            | P1     |

| Header        | 是否显示头像、头像位置、姓名字号、联系信息排列方式                                            | P1     |

**通用约束**：

- 所有 Customize 配置存于 `ResumeSettings`，与 Resume 一对一关联。
- Customize 任何改动 → 实时反映到右侧 Preview，防抖 250ms。
- 单条 Customize 改动支持 Undo / Redo。

### 8.4 AI 工具（AI Tools）

**优先级**：P1（v1.0 GA 必备，但允许用户不开启）

| ID    | 功能           | 描述                                                                                            | 验收要点                                       |
| ----- | -------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| AI-01 | Key 配置       | Settings → AI 面板填入 Anthropic API Key；Key 存于系统 keyring                                  | Key 不出现在简历 JSON / 日志中                 |
| AI-02 | Bullet 润色    | Experience / Volunteering bullet 编辑态出现「AI 润色」按钮 → 流式返回 3 个改写候选            | 候选可点击应用；接受 / 拒绝均记录到 Undo 栈     |
| AI-03 | Summary 改写   | Summary 编辑态出现「AI 改写」按钮 → 流式返回 1 个改写版本                                       | 风格可选（简洁 / 详尽 / 数字驱动）             |
| AI-04 | Cover Letter   | AI Tools 面板「生成 Cover Letter」→ 选简历 + 粘贴 JD → 流式生成草稿                            | 生成后进入 Cover Letter 编辑器                 |

## 9. 设计原则（UX）

1. **本地优先**：所有数据默认存本地；任何网络请求必须用户显式触发或同意。
2. **就地编辑**：编辑动作不跳转新页面；section 卡片三态机统一所有 section 的编辑路径。
3. **可逆**：任何破坏性操作（删除、清空、AI 替换）都进入 Undo 栈；删除文件走系统回收站。
4. **所见即所得**：Preview 与导出视觉一致；Customize 改动实时反馈。
5. **可扩展显式化**：新增 section / 新增模板 / 新增导出格式都按「加文件」的路径，框架不变。
6. **错误友好**：错误信息必须告知用户「发生了什么 + 下一步做什么」，不暴露原始 stack。
7. **键盘可达**：核心动作（保存、撤销、添加、关闭浮窗）均有键盘快捷键，且在按钮 tooltip 中显示。
8. **隐私显式化**：涉及数据出网的功能（AI、导入第三方文件）必须有明确的二次提示。

## 10. 非功能需求

### 性能

| 指标                            | 目标                |
| ------------------------------- | ------------------- |
| 冷启动到 Editor 可交互           | ≤ 2 秒（M1 / 中端 PC） |
| 简历切换响应                    | ≤ 200ms             |
| Preview 防抖更新                | 250ms 后渲染        |
| PDF 导出（单页）                | ≤ 3 秒              |
| ATS 评分                         | ≤ 1 秒              |
| AI 单次调用 P95                  | ≤ 8 秒（取决于网络） |
| 内存峰值（含 10 份简历）         | ≤ 350 MB            |

### 可靠性

- JSON 写入原子化（tempfile + rename）。
- 写入失败回滚旧文件；用户层面可见明确错误。
- AI 调用失败时不破坏已有内容，保留原文。

### 安全

- AI Key 存系统 keyring，绝不入文件系统明文。
- 导出路径必须在用户授权范围内，不允许写到系统目录。
- 模板包不允许任意脚本执行（HTML 渲染禁用 `<script>` 与远程资源）。
- 日志默认不含简历内容；启用 debug 日志需用户显式开启。

### 可访问性

- 所有交互元素有 `aria-label`。
- 键盘 Tab 顺序合理。
- 色彩对比度 ≥ WCAG AA。

### 兼容性

- 系统：macOS 12+、Windows 10+、Linux（X11 / Wayland）。
- 屏幕：最小 1280 × 720；适配 Retina / HiDPI。

## 13. 风险与假设

### 假设

- 用户接受桌面应用形态（不要求浏览器版）。
- Anthropic API 在用户区域可达；不可达地区禁用 AI 模块即可。
- 桌面端 PDF 引擎（headless_chrome / typst / printpdf）至少有一个能落地像素级还原。

### 风险

| 风险                                  | 影响     | 缓解                                                         |
| ------------------------------------- | -------- | ------------------------------------------------------------ |
| Tauri 2 在某些 Linux 发行版兼容性差    | 中       | CI 矩阵覆盖 Ubuntu / Fedora / Arch；提供 AppImage           |
| PDF 渲染与 HTML Preview 不一致         | 高       | 选定渲染路径后做端到端视觉回归（pixel diff）                |
| AI 输出质量参差不齐                    | 中       | 提供「拒绝」一键回退；候选数 ≥ 3 给用户选择                  |
| 中文字体在导出 PDF 缺失                 | 高       | 内置 NotoSansCJK 子集；模板字体可回退到系统字体              |
| 用户简历数据丢失                       | 极高     | 写入原子化 + 删除走回收站 + 每次保存生成时间戳备份（保留 N 份）|
| 模板生态规模不足                       | 中       | v1.0 自带 4-8 套；预留用户加载本地包接口                    |
| ATS 评分规则与真实 ATS 系统差异        | 中       | 文案明确「估算」；提供改进建议而非绝对分数                  |
